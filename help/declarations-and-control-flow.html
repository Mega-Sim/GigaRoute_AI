Declarations and Control Flow

11 entries, for example: event, on, routine / function, call / direct event call, if / else if / else, and more. Text is generated from the Help window of GigaRoute Simulation Studio.

Declarations

event

Purpose
Declares unified GRS logic. Canonical engine events and user-defined callable events use the same declaration kind.
Syntax
begin name(args) event
    ...
end
Example
begin calc.double(x) event
    return(x * 2);
end
compiler-checked
Notes
Parameters are comma-separated identifiers. __gigaroute.* is reserved.
Related
on, routine, function, call, return

on

Purpose
Compatibility declaration for a canonical engine-bound event.
Syntax
on <canonical-event> { ... }
Example
on vehicle.pickup {
    print(vehicle.id);
}
compiler-checked
Notes
Use event for new code. on accepts canonical events only and cannot declare parameters.
Related
event, canonical events

routine / function

Purpose
Compatibility aliases lowered to the same unified event implementation.
Syntax
routine name { ... }
function name(args) { ... }
Example
function calc.tax(v) {
    return(v * 0.1);
}
compiler-checked
Notes
New Studio templates use begin NAME event ... end. The older event NAME { } form and these aliases remain accepted for compatibility.
Related
event, call, return

call / direct event call

Purpose
Invokes a user-defined GRS event. Expression-position calls return the event's return value.
Syntax
call(eventName(args))
eventName(args)
Example
begin calc.double(x) event
    return(x * 2);
end

begin model.init event
    set(result, calc.double(4));
end
compiler-checked
Notes
Parameters are positional.
Related
event, return, parameters

Control Flow

if / else if / else

Purpose
Executes conditional branches.
Syntax
if (<condition>) { ... }
} else if (<condition>) { ... }
} else { ... }
Example
if (vehicle.phase == "idle") {
    print("idle");
}
compiler-checked
Notes
Conditions use the GRS expression surface.
Related
comparison operators, &&, ||, !

while

Purpose
Repeats a block while its condition is true.
Syntax
while (<condition>) { ... }
Example
while (count < 5) {
    inc(count, 1);
}
compiler-checked
Notes
Use wait/resource/order-list coordination when model time must advance.
Related
break, continue, wait

for

Purpose
Iterates a snapshot list such as vehicle.schedjobs.
Syntax
for (<item> in <iterable>) { ... }
Example
for (job in vehicle.schedjobs) {
    print(job.type);
}
compiler-checked
Notes
The iterable is evaluated once when the loop begins.
Related
vehicle.schedjobs, break, continue

break

Purpose
Leaves the innermost while/for loop.
Syntax
break
Example
if (job.type == "move") {
    break
}
compiler-checked
Notes
Only valid inside a loop.
Related
while, for, continue

continue

Purpose
Skips to the next iteration of the innermost loop.
Syntax
continue
Example
if (job.alive == false) {
    continue
}
compiler-checked
Notes
Only valid inside a loop.
Related
while, for, break

return

Purpose
Returns a value from the current user-defined event/call.
Syntax
return(value)
Example
return(vehicle.id);
compiler-checked
Notes
The compiled runtime also has a null return at the natural end of an event.
Related
event, call

return (no value)

Purpose
Returns from the current user-defined event without a value.
Syntax
return
return(value)
Example
if (done) {
    return
}
compiler-checked
Notes
A bare return produces null. return(value) preserves the existing return-value behavior.
Related
event, call, return(value)
