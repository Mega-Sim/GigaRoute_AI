Call from model.init, e.g. preload_buffer_cell("BUFFER_2_R1_C1"). The Cell becomes occupied exactly as after a completed store, so `move from buffer` can take it later.

Buffer_Move_Cell_Wait(source_cell, target_cell [, vehicle])

Purpose
Moves the FOUP in one Buffer Cell into another empty Buffer Cell and waits until it is set down (GRS sentence: `move from buffer A to buffer B`).
Syntax
call Buffer_Move_Cell_Wait(source_cell, target_cell [, vehicle])
Notes
The source Cell is freed at Pickup and the target Cell becomes occupied at Setdown. Rejected (logged) when the source is empty/reserved or the target is occupied/reserved/unreachable.

Declare_Attribute_Type(name, type)

Purpose
Declares the expected type (Bool/Integer/Number/String/Time/Distance/EntityRef) for a custom Attribute name.
Syntax
call Declare_Attribute_Type(name, type)
Notes
Once declared, set()/configure() writes of a mismatched Value kind are rejected (returns false) instead of silently coercing to 0/"". Integer/Number/Time/Distance all gate on the same underlying Number kind -- GRS Value has no narrower numeric type, so the distinction is documentation/unit intent. Does not retroactively validate values already written.

Humanoid_Define_Obstacle(name, x1_m, y1_m, x2_m, y2_m [, level_id [, z_min_m [, z_max_m]]])

Purpose
Defines a rectangular obstacle Humanoids walk around (optionally limited to a height range).
Syntax
call Humanoid_Define_Obstacle(name, x1_m, y1_m, x2_m, y2_m [, level_id [, z_min_m [, z_max_m]]])
Notes
Levels without obstacles keep straight-line x route_factor. A walk with no route is rejected. Already planned walks are not re-planned. Height range (default floor to ceiling): an obstacle blocks a Humanoid only if z_max > 0.1 m and z_min < its height, so a low curb is stepped over and an overhead beam is walked under. AMR positions at request time are treated as temporary obstacles on the walk.

Humanoid_Remove_Obstacle(name)

Notes
Affects walks requested afterwards.

Humanoid_Define_Zone(name, x1_m, y1_m, x2_m, y2_m [, capacity [, level_id]])

Purpose
Defines a corridor/area that at most `capacity` (default 1) Humanoids may be walking through at once.
Syntax
call Humanoid_Define_Zone(name, x1_m, y1_m, x2_m, y2_m [, capacity [, level_id]])
Notes
A Humanoid entering from outside waits at the entrance until the zone has room (first-requested first-served). Only walking time inside the zone is counted; standing Humanoids and other vehicle types do not occupy it. Zones on one level must not overlap.
