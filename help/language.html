GRS language basics

GRS (GigaRoute Script) is the script language of GigaRoute Simulation Studio Model Logic. Every code sample on this page was run through the GRS compiler front end; the samples marked as errors are rejected by it.

Source files

GRS source files use the .grs extension and UTF-8 text. A program is a set of event blocks; a Studio Model Logic file is plain GRS source.

Two block styles

Logic is declared with events. A block is written either with braces or with begin ... end; both compile to the same event model. Blocks must span several lines: the compiler rejects a block written on one line.

Brace style — compiles

event model.init {
    print("hello");
}

begin ... end style (no parentheses or semicolons needed) — compiles

begin model.init event
    print "hello"
end

One-line block: rejected (GRS_SURFACE_NATIVE_STRUCTURE_REQUIRED) — rejected by the compiler

event model.init { print("hello"); }

Compiler message: GRS_SURFACE_NATIVE_STRUCTURE_REQUIRED: GRS source must declare logic with event (or on/routine/function compatibility) { } blocks, or with native 'begin <name> event ... end' blocks

Statements and variables

Statements are written like function calls, one per line, usually ending with a semicolon. set assigns a value to a symbol or attribute; inc and dec change a number.

set / inc / dec / print — compiles

event model.init {
    set(counter, 0);
    inc(counter, 1);
    dec(counter, 1);
    print("counter", counter);
}

Literals and operators

Numbers, strings in double quotes, true, false and null are literals. Operators: + - * / == != < <= > >= && || !

Arithmetic, comparison, boolean, literals — compiles

event model.init {
    set(ok, 1 + 2 * 3 >= 7 && !(4 == 5));
    set(name, "BOX01");
    set(flag, true);
    set(none, null);
}

Comments

Line comments start with // and block comments are written /* ... */.

Comments — compiles

event model.init {
    // line comment
    /* block
       comment */
    print("x");
}

Conditions

if / else if / else choose a branch from a condition.

if / else if / else — compiles

event model.init {
    if (counter > 10) {
        print("big");
    } else if (counter > 5) {
        print("medium");
    } else {
        print("small");
    }
}

Loops

while repeats while its condition is true; for iterates a list; break leaves a loop; continue skips to the next iteration.

while with continue and break — compiles

event model.init {
    set(count, 0);
    while (count < 5) {
        inc(count, 1);
        if (count == 3) {
            continue;
        }
        if (count == 4) {
            break;
        }
    }
}

for over a list — compiles

event model.init {
    for (job in vehicle.schedjobs) {
        print(job.type);
    }
}

User events and calls

An event with parameters can be called like a function and can return a value. Parameters are positional.

Declare and call an event — compiles

event calc.double(x) {
    return(x * 2);
}

event model.init {
    set(result, calc.double(4));
    print(result);
}

Compatibility forms

on, routine and function are accepted for compatibility and compile to the same event; new code should use event.

on <canonical-event> — compiles

on vehicle.pickup {
    print(vehicle.id);
}

function — compiles

function calc.tax(v) {
    return(v * 0.1);
}

Compile errors you will see

These diagnostics come from the GRS compiler. A program with any error cannot be run.

Unclosed block (GRS_SURFACE_UNCLOSED_BLOCK) — rejected by the compiler

event model.init {
    print("a");

Compiler message: GRS_SURFACE_UNCLOSED_BLOCK: one or more GRS '{' or 'begin' blocks are not closed

Removed verb (GRS_SURFACE_REMOVED_ACTION): use move_to(target) — rejected by the compiler

event model.init {
    travel(ST01);
}

Compiler message: GRS_SURFACE_REMOVED_ACTION: travel() was removed; GigaRoute has a single movement verb -- use move_to(<target>)

Wrong argument count (GRS_SURFACE_ARGUMENT_COUNT) — rejected by the compiler

event model.init {
    wait();
}

Compiler message: GRS_SURFACE_ARGUMENT_COUNT: wait expects 1 argument(s)

Compile check is not a run check. The compiler checks structure and argument counts. For example, calling a function name that does not exist still compiles; problems of that kind appear when the model is run.
