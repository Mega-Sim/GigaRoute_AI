Vehicle Attributes

vehicle.id

Purpose
Dense Vehicle identifier for the current Vehicle actor.
Syntax
vehicle.id
Example
print(vehicle.id);
compiler-checked
Notes
Read-only physical identity.
Related
vehicle.station, vehicle.phase

vehicle.station / from / destination

Purpose
Reads the current Station, job source and job destination from the SimulationEngine snapshot.
Syntax
vehicle.station
vehicle.from
vehicle.destination
Example
print(vehicle.station, vehicle.destination);
compiler-checked
Notes
Returns null when the corresponding Station is invalid/unset.
Related
vehicle.phase

vehicle.phase / status

Purpose
Returns the current physical phase as a string: idle, retrieving, pickup, moving or setdown.
Syntax
vehicle.phase
vehicle.status
Example
if (vehicle.phase == "idle") { ... }
Notes
SimulationEngine remains the physical truth owner.
Related
vehicle.station

vehicle.schedjobs

Purpose
Returns the current Vehicle's live script ScheduleJob handles as a list.
Syntax
vehicle.schedjobs
Example
for (job in vehicle.schedjobs) { print(job.type); }
compiler-checked
Notes
The list is scoped to one Vehicle; no Vehicle x Job fleet scan is required.
Related
vehicle.current_schedjob, ScheduleJob

vehicle.current_schedjob

Purpose
Gets/sets the selected current ScheduleJob for the Vehicle.
Syntax
vehicle.current_schedjob
Example
set(vehicle.current_schedjob, job);
compiler-checked
Notes
An incomplete explicitly selected retrieve can reserve an Idle Vehicle until its endpoints are supplied.
Related
preempt, ScheduleJob

Vehicle zone

Purpose
Sets or reads a logical Vehicle zone such as building, floor, or operating area.
Syntax
set(vehicle.zone, "ZONE")
set_vehicle_zone(vehicle, "ZONE")
vehicle_zone(vehicle)
Example
set(vehicle.zone, "FAB_A_7F");
print(vehicle_zone(vehicle));
compiler-checked
Notes
Zone is logical metadata. It does not automatically change routing, dispatch, Following, or Sensor behavior. Blank means UNASSIGNED.
Related
Path zone, current path zone, Simulation Setup Vehicle Zone

Path / Routing

Path zone

Purpose
Reads or changes the logical zone assigned to a directed Path ID.
Syntax
path_zone(pathId)
set_path_zone(pathId, "ZONE")
Example
set_path_zone(12, "FAB_B_3F");
print(path_zone(12));
compiler-checked
Notes
This changes logical runtime metadata only. It does not change route weight, direction, physical length, or automatically restrict route search. Workspace Selected Path Zone is the authoring source for Path.zone.
Related
Vehicle zone, route weight, Workspace Selected Path Zone

Path type (rail type name)

Purpose
Reads the rail type attribute of a directed Path ID: its type name and whether the rail belongs to OHT or AGV.
Syntax
path_type_name(pathId)
path_type(pathId)
vehicle_type_name(vehicle)
vehicle_path_type_name(vehicle)
Example
print(path_type(12), path_type_name(12));
print(vehicle_type_name(vehicle), vehicle_path_type_name(vehicle));
compiler-checked
Notes
The type name is authored in Workspace (select rails and a Vehicle object, right-click Type Name...), by DXF layer AGV_PATH* (rail kind default), or by the model.module type_name field. A Vehicle spawns on the rails whose type name equals its own. Read-only at run time; it does not restrict routing.
Related
Path zone, model.module type_name

Vehicle Attributes

Current Path zone

Purpose
Returns the zone of the Path the Vehicle currently occupies.
Syntax
vehicle_path_zone(vehicle)
current_path_zone(vehicle)
Example
if (vehicle_path_zone(vehicle) == "FAB_A_7F") {
    print("vehicle is in A 7F");
}
compiler-checked
Notes
The value is read-only through these accessors. Use set_path_zone(pathId, zone) or Workspace Path settings to edit Path zone. Off-map Vehicles return an empty string.
Related
Vehicle zone, Path zone
