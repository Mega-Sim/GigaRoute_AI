Model snap

Purpose
Runs after a completed Model session snapshot boundary. The event observes the model at the exact committed simulation time, without creating a UI render timer.
Syntax
begin model.snap event
    ...
end
Example
begin model.init event
    set snapCount = 0
end
begin model.snap event
    inc snapCount by 1
    print "model snap", snapCount to log
end
Notes
The first event runs at simulation time 0 after Init. Thereafter one event runs for each successful forward ModelExecutionSession.advanceTo() call, after all physics modules finish. Re-reading the immutable snapshot, pausing, or advancing to the same time does not fire it again. Each module executes its own defined model.snap handler, if present. This is not triggered by Qt paint/repaint and it is not a request to save the project file. 'begin model snap event' is accepted as an alias. Normal GRS restrictions on wait and functions still apply.
Related
model.init, Time duration, print to log

Vehicle event syntax

Purpose
Public Vehicle event syntax shared by OHT, AGV and AMR: vehicle. followed by the event name with underscores (pickup, setdown, speed_change, resume_to_drive, start_to_move, arrived_at_station, job_finished, job_selection, job_assigned, decelerate_to_destination, passing_station, destination_change). The old space form (begin Vehicle pickup event) was removed.
Syntax
begin vehicle.<event_name> event
    ...
end
Example
begin vehicle.job_assigned event
    print "job assigned" to log
end
Notes
The GRS compiler lowers these event declarations to the engine's existing internal callbacks. Existing project event keys still load for compatibility. The event actor Vehicle is available as this Vehicle. The same header works in OHT, AGV and AMR modules; steer change and for each ... in Vehicle are OHT only.

Vehicle OHT / AGV / AMR differences

Purpose
The vehicle.<event_name> header is the only spelling: there are no separate Def_OHT / Def_AGV / Def_AMR headers. It works in OHT, AGV (AMR Core Fixed Path) and AMR modules with the same 12 event names.
Syntax
begin vehicle.<event_name> event
    ...
end
Example
begin vehicle.passing_station event
    print "passing ", vehicle.passing_station_name to log
end
Notes
Observation is enabled only for events you implement and never changes physics. This Vehicle is the actor Vehicle. passing station radius for AMR / AGV is max(250 mm, body radius); vehicle.passing_station_name reads the station just passed. wait is not allowed inside a passing station event (the vehicle is moving through the Station): compile error GRS_SEMA_WAIT_IN_PASSING_STATION_EVENT. for each ... in Vehicle is OHT only: an AMR / AGV module that uses it is rejected before the run.

Humanoid event syntax

Purpose
Humanoid uses the same 12 event names (begin humanoid.pickup event, ...). Job means humanoid_transfer; pickup/setdown fire when humanoid_pick/humanoid_place start.
Syntax
begin humanoid.<event_name> event
    ...
end
Example
begin humanoid.job_finished event
    print "done ", this Humanoid to log
end
Notes
this Humanoid is humanoid_self(); humanoid_event_place() reads the place just passed (within 400 mm) inside passing station. resume to drive occurs only in live walking. wait is not allowed inside a passing station event (the vehicle is moving through the Station): compile error GRS_SEMA_WAIT_IN_PASSING_STATION_EVENT.
