Events

32 reference entries, updated from current product main (2026-10-19). Newly added examples are not claimed compiler-checked until separately tested.

New equipment events should use begin Def_OHT pickup event and corresponding Def_AMR, Def_AGV or Def_Humanoid headers. Older dotted callback names remain supported for saved model compatibility, not as preferred new equipment syntax. model.init remains valid.

Conveyor job lifecycle

Purpose
Receives actual creation, movement, blocked, exit-ready, downstream-release and completion callbacks from the Conveyor job.
Syntax
begin conveyor.job_created event
    ...
end
begin conveyor.job_moved event
    ...
end
begin conveyor.blocked event
    ...
end
begin conveyor.exit event
    ...
end
begin conveyor.released event
    ...
end
begin conveyor.job_completed event
    ...
end
Example
begin conveyor.exit event
    print(module_id, load_id);
    call_transport("floor_fleet", load_id, "Floor_Pick", "Floor_Drop");
end
compiler-checked
Notes
Use request from <entry> to <exit> to enqueue real work. every schedules its first request after the specified interval. lifecycle symbols identify the module, Job, Load and actual microsecond timestamp and remain available after a wait. conveyor.exit is the stop-distance handoff-ready boundary; conveyor.released fires after downstream acceptance. conveyor.job_completed remains the ordinary completion boundary.
Related
Studio model modules, every_event, request_transport, call_transport

job.selected

Purpose
Runs once when a live ScheduleJob becomes a Vehicle's current_schedjob.
Syntax
begin job.selected event
    ...
end
Example
begin job.selected event
    print(this.id, this.type, this.vehicle, this.location);
end
compiler-checked
Notes
Existing engine callback name, kept for saved-model compatibility. For new OHT GRS use `begin Def_OHT job selection event`. This callback was not removed. Implemented. The event actor is the ScheduleJob handle. Re-setting the same current job does not fire again. preempt() fires only when it actually changes the current job.
Related

Def_OHT event syntax

Purpose
Public OHT event syntax. Write readable event phrases instead of authoring the engine's dotted callback identifiers.
Syntax
begin Def_OHT <event name> event
    ...
end
Example
begin Def_OHT job assigned event
    print "job assigned" to log
end
Notes
The GRS compiler lowers these event declarations to the engine's existing internal callbacks. Existing project event keys still load for compatibility. OHT actor is available as this OHT when applicable.

Def_AMR / Def_AGV event syntax

Purpose
AMR and AGV (AMR Core Fixed Path) use the same 12 event phrases as Def_OHT: pickup, setdown, speed change, resume to drive, start to move, job finished, job selection, decelerate to destination, arrived at station, job assigned, passing station, destination change.
Syntax
begin Def_AMR <event name> event
    ...
end
Example
begin Def_AMR passing station event
    print "passing ", vehicle.passing_station_name to log
end
Notes
Def_AGV and Def_AMR lower to the same events. steer change is OHT only. Observation is enabled only for events you implement and never changes physics. This AMR / this AGV is the actor Vehicle. passing station radius is max(250 mm, body radius); vehicle.passing_station_name reads the station just passed.
Related
Def_AMR, Def_AGV, AMR, AGV, GRS Events

Def_Humanoid event syntax

Purpose
Humanoid uses the same 12 event phrases. Job means humanoid_transfer; pickup/setdown fire when humanoid_pick/humanoid_place start.
Syntax
begin Def_Humanoid <event name> event
    ...
end
Example
begin Def_Humanoid job finished event
    print "done ", this Humanoid to log
end
Notes
this Humanoid is humanoid_self(); humanoid_event_place() reads the place just passed (within 400 mm) inside passing station. resume to drive occurs only in live walking. steer change is OHT only.

Def_Humanoid, Humanoid, GRS Events
