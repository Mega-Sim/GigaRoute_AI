Conveyor job lifecycle

Purpose
Receives actual creation, movement, blocked, exit-ready, downstream-release and completion callbacks from the Conveyor job.
Syntax
begin conveyor.job_created event
    ...
end
begin conveyor.job_moved event
    ...
end
begin conveyor.blocked event
    ...
end
begin conveyor.exit event
    ...
end
begin conveyor.released event
    ...
end
begin conveyor.job_completed event
    ...
end
Example
begin conveyor.exit event
    print(module_id, load_id);
    call_transport("floor_fleet", load_id, "Floor_Pick", "Floor_Drop");
end
compiler-checked
Notes
Use request from <entry> to <exit> to enqueue real work. every schedules its first request after the specified interval. lifecycle symbols identify the module, Job, Load and actual microsecond timestamp and remain available after a wait. conveyor.exit is the stop-distance handoff-ready boundary; conveyor.released fires after downstream acceptance. conveyor.job_completed remains the ordinary completion boundary.
Related
Studio model modules, every_event, request_transport, call_transport

job.selected

Purpose
Runs once when a live ScheduleJob becomes a Vehicle's current_schedjob.
Syntax
begin job.selected event
    ...
end
Example
begin job.selected event
    print(this.id, this.type, this.vehicle, this.location);
end
compiler-checked
Notes
Implemented. The event actor is the ScheduleJob handle. Re-setting the same current job does not fire again. preempt() fires only when it actually changes the current job.
Related
ScheduleJob, vehicle.current_schedjob, preempt, job.finished

job.finished

Purpose
Runs when the committed physical job has fully completed and the Vehicle reaches the authoritative Idle handoff.
Syntax
begin job.finished event
    ...
end
Example
begin job.finished event
    print(this.id, this.type, this.vehicle, this.load);
end
compiler-checked
Notes
Implemented. This is later than vehicle.setdown: configured Setdown dwell must finish first. The event actor is the completed ScheduleJob handle.
