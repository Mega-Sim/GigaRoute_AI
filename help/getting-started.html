Getting Started

14 reference entries, updated from current product main (2026-10-19). Newly added examples are not claimed compiler-checked until separately tested.

For new models: start with Automatic model binding. Explicit model.module settings below remain available for existing and advanced models.

GRS file

Purpose
Simulation Studio Model Logic source file.
Syntax
*.grs
Example
begin model.init event
    print("ready");
end
compiler-checked
Notes
GRS uses UTF-8 text. Both native { } blocks and the supported begin <name> event ... end surface compile to the same GRS event model; legacy engine event bindings are retained for existing GRS projects.
Related
event, Model Logic

Studio Station binding

Purpose
Connects each declared module to its own physical domain before Run.
Syntax
entry_station / exit_station / level_id / elevation_mm
Example
set(entry_station, "Input_A");
set(exit_station, "Output_A");
set(level_id, 0);
compiler-checked
Notes
OHT requires Rail-attached Stations. Conveyor requires Stations on one uniquely connected nonbranching LINE path; curves and ambiguous routes are rejected. AMR requires floor Stations, not overhead Rail Stations. Use the existing Station menu's AMR floor Station action to create Level 0 ground-plane Stations. File names, print text and demo Station prefixes do not select equipment. Cross-module logical Load handoff uses call_transport(target_module, load_id, from_station, to_station).
Related
Studio model modules, Workspace Station

Actual From-To CSV

Purpose
Defines recurring From-To job releases used by Auto Simulation and Static Analysis.
Syntax
Time Interval,From,To
Example
557.3752984,E0001,E0108
compiler-checked
Notes
Time Interval is seconds between recurring releases for that row. Static Analysis uses moves/hour = 3600 / Time Interval. Auto Simulation schedules first_due = Time Interval and then previous_due + Time Interval, so the first job is not forced at t=0.

Studio model modules

Purpose
Runs newly authored OHT, AMR and Conveyor modules together, including Conveyor-only models.
Syntax
begin model.module event
    set(module_id, "belt_alpha"); set(runtime_kind, "conveyor"); ...
end
Example
begin model.module event
    set(module_id, "belt_alpha");
    set(runtime_kind, "conveyor");
    set(entry_station, "Input_A");
    set(exit_station, "Output_A");
    set(job_source, "script");
    set(speed_mps, 1);
end
begin model.init event
    every 8 sec call supply
end
begin supply event
    request from Input_A to Output_A
end
compiler-checked
Notes
Declare ownership in each source file. Same module_id combines files; different modules keep separate events. Use runtime_kind oht, amr or conveyor. One fleet per OHT/AMR kind; multiple Conveyor modules are supported. Station names must match the current drawing and carrier. Compile applies the entire valid model; any error blocks a new Run. No manifest or saved .grproj is required. Optional set(run_until_seconds, 7200) in model.module overrides Studio Run Until; conflicting module declarations are rejected. Pause/Resume retains the active program; Restart uses edited sources. Existing undeclared single-runtime models retain their own execution path. For newly authored simplified GRS, see Automatic model binding: Studio selects Station/Level ownership from literal transport requests, without requiring a model declaration.
Related
model.init, request_transport, every_event, Studio Station binding

Vehicle asset

Purpose
Selects an OHT or AMR Equipment instance whose embedded GLB is used by the matching runtime renderer.
Syntax
begin model.vehicle_type.oht event
end
begin model.vehicle_asset.<project_instance_name> event
end
Example
begin model.vehicle_type.oht event
end
begin model.vehicle_asset.oht_01 event
end
compiler-checked
Notes
The selector suffix matches Equipment instance_name case-insensitively. With no selector, exactly one instance in the matching category (OHT Vehicle or AMR) is bound automatically. Zero or multiple candidates retain the legacy type-specific renderer and emit GRS_VEHICLE_ASSET_FALLBACK. A missing or wrong-type explicit selector blocks Run. The original static placement is hidden only while that View has matching runtime snapshots.
Related
Vehicle runtime type, Workspace Equipment, Simulation Studio 3D

model.module type_name

Purpose
Declares the rail type name a module's Vehicles spawn on.
Syntax

    set(module_id, "agv_a");
    set(runtime_kind, "agv");
    set(type_name, "LINE_A");
end
Example

compiler-checked
Notes
Supported for runtime_kind oht and agv. vehicle_count Vehicles spawn on rails whose type name is LINE_A (OHT: on that rail's Stations; AGV: on that rail). Without type_name, Workspace Vehicle objects with a Type Name, or the established placement, are used.

Global Init / default OHT AMR Humanoid

Purpose
Create the default OHT, AMR and Humanoid counts directly from one global initialization event.
Syntax
begin model.init event
    vi_OHT = 10
    vi_Humanoid = 3
    vi_AMR = 3
end
Example
begin model.init event
    vi_OHT = 10
    vi_Humanoid = 3
    vi_AMR = 3
end
begin OHT.init event
    set i = 0
    while i < vi_OHT
    begin
        inc i by 1
        print "OHT", i, " is initialized" to log
    end
end
begin Humanoid.init event
    set i = 0
    while i < vi_Humanoid
    begin
        inc i by 1
        print "Humanoid", i, " is initialized" to log
    end
end
begin AMR.init event
    set i = 0
    while i < vi_AMR
    begin
        inc i by 1
        print "AMR", i, " is initialized" to log
    end
end
Notes
New global-init script has exactly one model.init with three positive integer vi_* values and these three typed events. At Compile the already-placed drawing supplies one OHT rail Level and one AMR floor Level (each with two distinct Stations); scripted Job Source is used with no synthetic traffic. Existing C++ Core creates vi_OHT/vi_AMR vehicles. Three-dimensional default humanoids are created at a floor Station. The typed init events run once at simulation time zero and print to the Studio message log. Other legacy and previously declared auto-bound scripts retain their existing behavior. All five previous helper initializers are NOT required for this opt-in.
Related
model.init, OHT.init, AMR.init, Humanoid.init, print to log

Automatic model binding

Purpose
Studio automatically connects literal GRS From-To Station requests to the Workspace OHT, AMR, AGV or Conveyor Runtime at Compile. No explicit module-binding declaration is required for this form.
Syntax
begin model.init event
    every 20 sec call supply
end
begin supply event
    request from Ceiling_Pick to Ceiling_Drop
end
Example
begin model.init event
    every 20 sec call supply
end
begin supply event
    request from Ceiling_Pick to Ceiling_Drop
end
Notes
Define real transport events; Studio determines Station carrier and Level once during Compile and keeps the original Runtime, scheduler and FOUP identity. Different Station owners can share one source when event ownership is unambiguous. Unknown/cross-Level Station pairs and multi-owner control flow reject Compile instead of guessing. Dynamic Station expressions and native-only models still require explicit ownership information in existing compatible projects until an internal owner-selection path is available. Existing Simulation Setup supplies fleet count/speed/pickup/setdown defaults. Saved explicit module declarations and older auto configuration files continue loading for compatibility; new GRS code should not author a module-binding event. An optional single model.init may call OHT_Init/AMR_Init/Humanoid_Init/ASRS_Init/Conveyor_Init and those typed routines are dispatched to matching physical runtimes.
Related
model.init, request_transport, every_event, Station binding, Simulation Setup

Common color_off

Purpose
Keeps original model colors by switching off phase or pose colors for matching OHT, AMR, AGV and Humanoid runtimes in the current Studio session.
Syntax
color_off()
color_off("oht")
color_off("amr")
color_off("agv")
color_off("humanoid")
Example
begin model.init event
    color_off()
end
Notes
Available in a declared Studio model session. With no argument all matching runtimes are affected, regardless of which module owns the call. One quoted type limits the scope; AMR and AGV are distinct. A missing target or unsupported argument fails with a GRS_COLOR_OFF diagnostic. Motion, Job timing and FOUP ownership are unchanged. Legacy oht.color_fixed / amr.color_fixed / humanoid.color_fixed remain accepted. Auto/legacy undeclared execution is unchanged.
Related
Studio model modules, oht.color_fixed, amr.color_fixed, humanoid.color_fixed

Automatic transfer target

Purpose
Hands a logical Load to the one existing prepared runtime that owns the destination Station route, with no explicit target module name.
Syntax
call_transport(load_id, "Floor_Pick", "Floor_Drop")
Example
begin conveyor.exit event
    call_transport(load_id, "Floor_Pick", "Floor_Drop")
end
Notes
Three arguments select a destination only when exactly one non-source runtime validates both Station endpoints. An unknown or ambiguous target is rejected with GRS_TRANSFER_NO_TARGET or GRS_TRANSFER_AMBIGUOUS_TARGET. The previous four-argument call_transport(target_module,load_id,from,to) remains unchanged. Source Setdown and destination capacity, event timing, and Load ownership all use the existing physical transfer protocol; no new polling or Load ID namespace is introduced.
Related
call_transport, Studio model modules, Station binding
