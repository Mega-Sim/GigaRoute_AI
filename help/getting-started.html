Studio model modules

Purpose
Runs newly authored OHT, AMR and Conveyor modules together, including Conveyor-only models.
Syntax
begin model.module event
    set(module_id, "belt_alpha"); set(runtime_kind, "conveyor"); ...
end
Example
begin model.module event
    set(module_id, "belt_alpha");
    set(runtime_kind, "conveyor");
    set(entry_station, "Input_A");
    set(exit_station, "Output_A");
    set(job_source, "script");
    set(speed_mps, 1);
end
begin model.init event
    every 8 sec call supply
end
begin supply event
    request from Input_A to Output_A
end
compiler-checked
Notes
Declare ownership in each source file. Same module_id combines files; different modules keep separate events. Use runtime_kind oht, amr or conveyor. One fleet per OHT/AMR kind; multiple Conveyor modules are supported. Station names must match the current drawing and carrier. Compile applies the entire valid model; any error blocks a new Run. No manifest or saved .grproj is required. Pause/Resume retains the active program; Restart uses edited sources. Existing undeclared single-runtime models retain their own execution path.
Related
model.init, request_transport, every_event, Studio Station binding

Studio Station binding

Purpose
Connects each declared module to its own physical domain before Run.
Syntax
entry_station / exit_station / level_id / elevation_mm
Example
set(entry_station, "Input_A");
set(exit_station, "Output_A");
set(level_id, 0);
compiler-checked
Notes
OHT requires Rail-attached Stations. Conveyor requires Stations on one uniquely connected nonbranching LINE path; curves and ambiguous routes are rejected. AMR requires floor Stations, not overhead Rail Stations. Use the existing Station menu's AMR floor Station action to create Level 0 ground-plane Stations. File names, print text and demo Station prefixes do not select equipment. Cross-module logical Load handoff uses call_transport(target_module, load_id, from_station, to_station).
Related
Studio model modules, Workspace Station

Vehicle runtime type

Purpose
Declares which physical Vehicle runtime owns this GRS model.
Syntax
begin model.vehicle_type.oht event
end
begin model.vehicle_type.amr event
end
Example
begin model.vehicle_type.oht event
end

begin model.init event
    print("OHT model ready");
end
compiler-checked
Notes
Declare exactly one marker for a typed model. Legacy Rail and Auto Simulation runs preserve Fleet Mode. Studio blocks an untyped GRS when the saved Fleet Mode is AMR; declare the intended type explicitly.

Vehicle asset

Purpose
Selects an OHT or AMR Equipment instance whose embedded GLB is used by the matching runtime renderer.
Syntax
begin model.vehicle_type.oht event
end
begin model.vehicle_asset.<project_instance_name> event
end
Example
begin model.vehicle_type.oht event
end
begin model.vehicle_asset.oht_01 event
end
compiler-checked
Notes
The selector suffix matches Equipment instance_name case-insensitively. With no selector, exactly one instance in the matching category (OHT Vehicle or AMR) is bound automatically. Zero or multiple candidates retain the legacy type-specific renderer and emit GRS_VEHICLE_ASSET_FALLBACK. A missing or wrong-type explicit selector blocks Run. The original static placement is hidden only while that View has matching runtime snapshots.
Related
Vehicle runtime type, Workspace Equipment, Simulation Studio 3D

Actual From-To CSV

Purpose
Defines recurring From-To job releases used by Auto Simulation and Static Analysis.
Syntax
Time Interval,From,To
Example
557.3752984,E0001,E0108
compiler-checked
Notes
Time Interval is seconds between recurring releases for that row. Static Analysis uses moves/hour = 3600 / Time Interval. Auto Simulation schedules first_due = Time Interval and then previous_due + Time Interval, so the first job is not forced at t=0.
Related
Actual From-To, Static Analysis, Auto Simulation

model.module type_name

Purpose
Declares the rail type name a module's Vehicles spawn on.
Syntax
begin model.module event
    set(module_id, "agv_a");
    set(runtime_kind, "agv");
    set(type_name, "LINE_A");
end
Example
set(runtime_kind, "oht");
set(type_name, "LINE_A");
compiler-checked
Notes
Supported for runtime_kind oht and agv. vehicle_count Vehicles spawn on rails whose type name is LINE_A (OHT: on that rail's Stations; AGV: on that rail). Without type_name, Workspace Vehicle objects with a Type Name, or the established placement, are used.
Related
Path type, runtime_kind, vehicle_count

Readable function names

Purpose
Model functions use Pascal_Underscore names; equipment acronyms remain uppercase.
Syntax
call OHT_System_Initialize()
call ASRS_Seed_Shelf_FOUP(101)
call AMR_System_Initialize()
call Conveyor_System_Initialize()
call Process_Complete()
Example
begin Process_Complete event
    print "process complete"
end
compiler-checked
Notes
Existing camelCase model declarations/calls remain compatible through one unambiguous case/underscore-insensitive alias. Canonical dotted hooks such as model.init, vehicle.pickup_complete, conveyor.blocked and equipment.load_arrived are unchanged. Existing snake_case runtime built-ins keep their implementation names; Help displays the same callable in readable Pascal_Underscore form.
