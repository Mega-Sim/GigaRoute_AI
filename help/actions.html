Actions

30 entries, for example: print, wait, wait_until, set, inc, and more. Text is generated from the Help window of GigaRoute Simulation Studio.

Core Actions

print

Purpose
Writes GRS output to the Script Print log and the Studio realtime log.
Syntax
print(value, ...)
Example
print("vehicle", vehicle.id, vehicle.phase);
compiler-checked
Notes
Arguments are rendered in order.
Related
Model Logic log

wait

Purpose
Suspends the current process until the requested simulation time has elapsed.
Syntax
wait(seconds)
Example
wait(0.25);
compiler-checked
Related
wait_until

wait_until

Purpose
Suspends the current process on the runtime wait-channel path until the condition can be re-evaluated after a wake.
Syntax
wait_until(condition)
Example
wait_until(counter >= 10);
compiler-checked
Notes
There is no periodic condition polling. Prefer explicit event/resource/order-list coordination for high-volume models.
Related
wait, order, Resource

clone source actor

Purpose
Forks script execution after cloning the selected Load actor.
Syntax
clone()
clone(load)
Example
clone(load);
compiler-checked
Notes
With no EntityHandle argument, clone uses the current actor. With an explicit Load handle, that Load is copied (ownership/location/destination/onboard/custom attributes) and the cloned execution branch continues with the copied Load as actor. This is runtime execution machinery, not a user-facing Process declaration.
Related
create, Load, Runtime Clone, Event execution model

disable_native_job_source

Purpose
Explicitly disables native Real/Random From-To release when the GRS model generates its own Load workload.
Syntax
disable_native_job_source()
Example
begin model.init event
    disable_native_job_source();
end
compiler-checked
Notes
Call this only when GRS itself owns demand generation. configure_motion() does not change workload ownership. Declared modules with job_source=script disable native generation during preparation and need no explicit disable call. A Native declaration conflicts with explicit script transport or source-disable actions.
Related
configure_motion, create, spawn_event, file_read_lines, Simulation Setup

oht.motion_off

Purpose
Turns off the OHT Pickup/Setdown transfer (Slide/Hoist) motion to keep the run light. Travel is unchanged.
Syntax
oht.motion_off()
Example
begin model.init event
    oht.motion_off();
end
compiler-checked
Notes
Call from model.init with no arguments. The Core pickup/setdown stop time is kept, so simulation results do not change; only the Slide/Hoist animation is skipped and the carrier switches between port and gripper at the handoff point. The setting applies to the OHT module that declares it.
Related
stk.motion_off, amr.motion_off, vehicle_dwell, Simulation Setup

oht.color_fixed

Purpose
Turns off the Vehicle-phase color change (Idle/Retrieving/Pickup/Moving/Setdown) so the OHT keeps its original model color.
Syntax
oht.color_fixed()
Example
begin model.init event
    oht.color_fixed();
end
compiler-checked
Notes
Call from model.init with no arguments. Only the display color changes; travel, pickup/setdown time and simulation results are unchanged. Useful for recording videos where a constant OHT color is easier to follow.
Related
oht.motion_off, set_vehicle_color, Simulation Setup

stk.motion_off

Purpose
Turns off STK Crane motion so the Crane does not move separately.
Syntax
stk.motion_off()
Example
begin model.init event
    asrs_stocker_initialize();
    stk.motion_off();
end
compiler-checked
Notes
Call from model.init with no arguments, before the first outbound request. Crane X/Z travel, Fork extend/retract and the pickup/deposit hold time all become 0, so each Crane job step completes immediately. Inventory, Port Lane and handoff events still occur in the same order. Rejected once the first outbound has started.
Related
oht.motion_off, amr.motion_off, asrs_stocker_initialize, asrs_request_first_outbound

amr.motion_off

Purpose
Turns off the AMR transfer (load/unload) motion setting.
Syntax
amr.motion_off()
Example
begin model.init event
    amr.motion_off();
end
compiler-checked
Notes
Call from model.init with no arguments. The AMR currently has no transfer motion, so the setting is only stored in the AMR engine; travel and the pickup/setdown stop time are unchanged.
Related
oht.motion_off, stk.motion_off

Transport

move_to

Purpose
Single GigaRoute movement verb. Station targets move a Vehicle through the existing physical route; an unresolved string target is treated as a Queue name.
Syntax
move_to(target)
Example
move_to(12);
move_to("ST01");
move_to("Q_WAIT");
compiler-checked
Notes
Station resolution has priority. travel() and move_into() are removed from product GRS.
Related
dispatch, Queue, Station

dispatch

Purpose
Creates a move ScheduleJob for a Vehicle. A Busy Vehicle keeps it in its own queue until an authoritative Idle boundary.
Syntax
dispatch(vehicle, station)
Example
dispatch(vehicle, "ST01");
compiler-checked
Related
ScheduleJob, preempt, cancel

claim

Purpose
Claims a Load for a Vehicle and creates a retrieve ScheduleJob.
Syntax
claim(load, vehicle)
Example
claim(load, vehicle);
compiler-checked
Notes
Same-owner claim is idempotent. A different Vehicle cannot claim an already claimed Load.
Related
Load, retrieve, ScheduleJob

cancel

Purpose
Cancels a live script ScheduleJob handle.
Syntax
cancel(job)
Example
cancel(job);
compiler-checked
Notes
If physical movement is already committed, route/pose are not rewound or teleported; the physical Load lifecycle still completes.
Related
ScheduleJob, claim, dispatch

configure

Syntax
configure(receiver, attribute, value)
configure(attribute, value)
Example
configure(vehicle, "priority", 5);
compiler-checked
Notes
Does not silently replace global Simulation Setup physical constants.
Related

preempt

Purpose
Makes an alive uncommitted ScheduleJob current. If the Vehicle is busy, the selection takes priority at the next Idle boundary.
Syntax
preempt(job)
preempt(vehicle, job)
Example
preempt(vehicle, urgentJob);
compiler-checked
Notes
Soft preempt only: no active-route deletion, rewind, teleport or forced phase mutation.
Related
vehicle.current_schedjob, ScheduleJob

Work_Accept

Purpose
Optional read-only acceptance predicate for explicit GRS claim(load, vehicle).
Syntax
begin Work_Accept(vehicle, load, pickup) event
    ...
end
Example
begin Work_Accept(vehicle, load, pickup) event
    return(pickup != null);
end
compiler-checked
Notes
Runs synchronously immediately before a new explicit script claim mutates Load/ScheduleJob state. It must return Bool. If absent, claim() behavior is unchanged. Native Random/Real dispatch and easy transport do not synthesize a Load just to call this predicate.
Related
claim, Load, ScheduleJob, read-only evaluation

Resources

use / get / reserve

Purpose
Acquires a named Resource. If it is at capacity, the current process waits until capacity becomes available.
Syntax
use(resource)
get(resource)
reserve(resource)
Example
get(R_MACHINE);
compiler-checked
Notes
Literal Resource names share one wake channel. Dynamic targets fall back to a single non-blocking acquisition attempt.
Related
free, release, Resource

free / release

Purpose
Releases a named Resource and wakes eligible waiters.
Syntax
free(resource)
release(resource)
Example
free(R_MACHINE);
compiler-checked
Related
use, get, reserve

compiler-checked

Related

Syntax
order(count)
Example

compiler-checked
Related
wait_ordered, OrderList

WIP / Traffic capacity pattern

Purpose
Models endpoint/WIP capacity with the existing Resource acquire/release and targeted wake path.
Syntax
get(WIP_RESOURCE)
...
free(WIP_RESOURCE)
Example
get(R_ST01_WIP);
free(R_ST01_WIP);
compiler-checked
Notes
Resource capacity is the authoritative capacity in this pattern. Station occupancy/reservation is physical Vehicle occupancy and is intentionally not treated as the same value.
Related
use, get, reserve, free, resource.capacity, station_occupancy_count
